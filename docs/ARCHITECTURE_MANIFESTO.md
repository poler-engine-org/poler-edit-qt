# Архітектурний маніфест POLER Edit: WYSIWYS проти сліпоти BigTech

> **«Парсер не повинен розгадувати координати принтера чи розгрібати заархівоване сміття. Парсинг має відбуватися з оптичної проекції того, що матеріалізовано у в'юпорті дисплея».**

---

## 1. Історичний тупик корпоративного підходу (Google, Microsoft, Adobe)

Сучасна IT-індустрія та великі мовні моделі (LLM/RAG) зіткнулися з катастрофічним падінням якості вилучення знань (до 30–40% втрати контексту). Корпорації десятиліттями намагаються вирішити цю проблему, нагромаджуючи важкі нейромережі поверх форматів, які ніколи не створювалися для розуміння тексту:

| Формат | Що насправді зчитує традиційний парсер | Архітектурний дефект |
|---|---|---|
| **PDF** | Інструкції печатного верстата PostScript (1993 рік): координати $(X, Y)$, розрізнені гліфи, розірвані таблиці, сміття колонтитулів і номерів сторінок. | **Принтерний глухий кут.** У PDF немає понять «речення», «абзац» чи «колонка». Спроба «відновити сенс» за координатами чернил на папері вимагає гігаватів OCR-обчислень і все одно склеює випадкові слова. |
| **DOCX / EPUB** | Гігантські заархівовані XML-контейнери (WordprocessingML). Кожне слово обвішане десятками тегів форматування, шрифтів, стилів і ревізій. | **XML-ентропія.** Щоб знайти один абзац тексту, парсер змушений будувати важке DOM-дерево в пам'яті, витрачаючи сотні мегабайт RAM на службове сміття. |
| **Markdown (`.md`)** | **Чистий структурований субстрат:** заголовки `#`, прямі абзаци, списки, формули LaTeX, метадані. | **0% сміття.** Ідеальний семантичний інваріант для RAG і людей: нульовий оверхед, повна відтворюваність. |

Корпорації загнали себе в пастку: замість спрощення носія вони будують евристики склеювання розірваних рядків і очищення колонтитулів, борючись із наслідками замість причини.

## 2. Принцип WYSIWYS (What You See Is What You Scan)

У **POLER Edit** реалізовано радикально інший підхід до взаємодії з текстом:

> **Якщо документ уже відрендерено — рендерер уже виконав усю брудну роботу за вас.**

1. Графічний рушій уже видалив службові XML-теги, приховані коментарі та керуючі коди.
2. Алгоритми верстки вже розставили переноси, склеїли слова та вибудували природний потік читання (зліва направо, зверху вниз).
3. Усі колонтитули та фонові артефакти відсікаються геометрією активного вікна.

Якщо брати дані **безпосередньо з буфера матеріалізованого в'юпорта** (зі спектра відображення дисплея), ми отримуємо 100% чистий, зв'язний людський сенс без жодного байта шуму.

## 3. Спектральне ковзне вікно 64 КБ та нульове копіювання (`mmap`)

Чому класичні редактори (VS Code, Notepad++, Kate) «задихаються» на великих файлах, а POLER Edit відкриває 10-гігабайтні дампи за 0.05 секунди?

```
Файл на диску (1–10 ГБ) 
   │
   ├── [OS Kernel Virtual Memory: mmap zero-copy]
   │
   ▼
В'юпорт ядра: активне спектральне вікно (~64 КБ) ──► Вміщується в L1/L2 кеш CPU
   │                                                   (швидкість шини пам'яті: десятки ГБ/с)
   ▼
Рендер у дисплей (Qt6) без завантаження всього файлу в RAM
```

### Фізика переваги:
1. **Zero-Copy через `memmap2`:** Жоден гігабайтний файл не копіюється в пам'ять процесу. Ядро ОС відображає сторінки файлу напряму у віртуальний адресний простір.
2. **Локальність кешу (L1/L2 Cache Line):** 64 КБ видимого діапазону даних гарантовано розміщуються в надшвидкому кеші процесора. Промахи пам'яті (Cache Misses) знижуються практично до нуля.
3. **Швидкість шини:** Переміщення курсору та пошук у в'юпорті виконуються з фізичною швидкістю кремнію, без алокацій на купі (`heap`).
4. **Імутабельна Piece-Table:** Будь-які редагування пишуться в окремий буфер правок (Append-only), зберігаючи оригінальний відображений файл недоторканим.

## 4. Висновок

Парсинг тексту, RAG та інтелектуальний аналіз майбутнього мають будуватися на **чистій пам'яті та видимій структурі**, а не на археології розірваних PDF-сторінок. 

POLER Edit доводить: системний редактор може споживати фіксовані 30 МБ оперативної пам'яті, миттєво сканувати гігабайтні масиви даних і давати чистий, незасмічений текстовий сигнал як для оператора, так і для автономних AI-агентів.
