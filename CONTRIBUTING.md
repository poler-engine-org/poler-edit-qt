# CONTRIBUTING — як контрибьютити в POLER Edit

Дякуємо за інтерес до проєкту! POLER Edit — суверенний текстовий редактор
(Qt6 GUI + ядро `poler-edit-core` на Rust, Zero-Copy Piece-Table поверх mmap).
Перш ніж надіслати PR, прочитайте цей файл повністю.

## 1. Принципи проєкту

1. **Ядро — Qt6 Widgets, нічого зайвого**: жодних KF6/KParts/Electron.
   Вся робота з текстом будь-якого розміру відбувається в ядрі; GUI рендерить
   лише видиме вікно рядків.
2. **RAM не залежить від розміру файлу** — це головний інваріант. Зміна, що
   робить споживання пам'яті пропорційним розміру файлу, не буде прийнята.
3. **Пошук не блокує редагування** — робота на іммутабельному снапшоті
   piece-table; після правок сесія перезапускається (debounce).
4. **Суверенність**: без телеметрії, без хмарних API, без відправки даних
   користувача на сервери. Залежності GUI — тільки Qt6; залежності ядра —
   мінімальні й кожна має виправдання.
5. **Детермінованість і паритет** — нова логіка ядра має мати
   диференціальний/property-тест проти «нудної» наївної моделі
   (див. `core/tests/`: `parity_random_text_random_needles`,
   `property_matches_naive_model`).

## 2. Визначення Done для зміни

- [ ] `cd core && cargo build --release` — без warnings.
- [ ] `cd core && cargo test --release` — зелене.
- [ ] Нова логіка ядра = новий паритет-тест (наївна модель → порівняння).
- [ ] README оновлено, якщо змінився користувацький поведінковий контракт.
- [ ] Коміт — атомарний, у present tense, з контекстом «чому» в тілі.

## 3. Процес

1. Форк → гілка `feat/<короткий-назва>` або `fix/<короткий-назва>`.
2. Зміни за принципами вище.
3. PR у `main` з заповненим шаблоном (галочка CLA обов'язкова).
4. CI (`release.yml`) має пройти.
